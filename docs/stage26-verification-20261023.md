# 阶段26：生成约定与输出诊断

本阶段处理生成请求与实际校验条件的落差，并解释真实响应为什么未完成。接收端回答模型、v3证据校验、默认1200输出、总预算和生产容量均未放宽，没有答案修补或自动付费重试。阶段12仍未验收。

## 实现与使用

`folder_assistant/contracts.py`保留原接收模型与`validate()`，在生成的请求Schema中补充已有条件：stated须有值和引用、blank/unknown不得带取值引用、不同subject_type对应的对象/引用条件、推断的假设及限制、差异/矛盾的双方依据与共同范围。条件是原检查的解释子集；实际引文字面匹配、对象和值的绑定、不同表格记录、双方原句去重及语义判断不能靠JSON Schema完成。

生成说明另标`GUIDE_VERSION=1`，不更改回答`schema_version=3`。逐项字段放在comparison，findings简洁概述，避免一张表重复输出；不以省略字段满足长度。实际接口仍为`response_format=json_object`，不是服务端强制Schema，不保证模型一定遵守。新请求保存说明版本及实际系统提示SHA，原有输入估算会计算新增文字，预算不足照常拒绝。

`output_diagnostics.py`独立描述已保存响应：输出上限、非正常结束、JSON/字段格式错误、引用或字段条件失败、结构已检查、尚未检查。length同时导致JSON不完整时，主诊断为输出上限，原invalid_schema问题仍保留；即使JSON完整，length也不计作该批完成。用量未知或用户停止时保留原响应，检查未执行便明确标not_run，不重试。结构已检查始终标语义未认证，不等于正式审稿通过。

桌面重启后，在“文件夹资料助手”发起新问题或分批整理，结果区可见“输出诊断”；选择批次查看该批的保存诊断。新摘要导出包含诊断及建议。旧记录不新增诊断、旧导出保持原样，查看历史不调用模型。显式拆小重做沿用既有操作和另行计费规则。本阶段不调整资料项目的背景发送策略，阶段25“未变化A文字仍在历史背景中重发”的限制继续存在。

## 调用前冻结的新资料配对诊断

诊断仅测试固定送达纯文本的请求层，不包含解析、检索、嵌入、重排或完整应用链，因此不提供RAG召回率或复杂资料全量性能结论。DeepSeek项目配置、默认非思考、单次输出1200、超时30秒、零重试；最多6次、50000 Token，估算每次输入加输出不得超过12000。所有实际返回用量已知。
