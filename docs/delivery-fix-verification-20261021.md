# 报告提交与运行记录修复

本轮完成错误汇总、简述组织、真实运行快照与恢复计数。调用前提交冻结的四题实测中，1题正常结束且完整审稿，1题在预算收尾中保存报告并完整审稿，另2题未获得当前有效关联与完整审稿。阶段12仍未验收；本编码助手负责开发及内容核对，不冒充独立第三方或用户人工验收。

## 代码行为

- `write_report`在保存前汇总可独立检查的任务约定、表头、算式、原句、来源、摘录错误，返回字段路径、错误代码和实际计量；拒绝时不改写报告或其质量/依据记录。无效来源之后的依赖检查仍须修复后重查，不宣称机械检查覆盖语义。
- 反馈最多24项、约6000字符；省略项计数和长消息截断显式标记。不会因为反馈被裁切而接受错误输入。
- 简述先组织核心答案、必要依据和限制；长引文放在引用字段。超长拒稿移出模型上下文时保留结构化错误，原始调用和错误完整留在trace。软目标、硬上限、审稿次数、步数和预算规则不变，不自动改ID、换摘录、补原文或继承过期claims。
- 按实际控制流累计工具请求、正常返回、错误返回和结果不确定次数，跨批次与检查点恢复继承。校验和重复拦截属于错误返回，不能称为函数已经执行失败；未返回有计数差额，厂商内部重试不混入工具次数。
- `read_notes`附上程序快照，记录送达并保留的文档版本数量及范围限制；它不是全库清单或全文阅读证明。快照仅实际送达部分进入execution证据，截断明确标记；独立审稿输入也携带实际累计记录。不从模型文本解析或生成这些统计。
