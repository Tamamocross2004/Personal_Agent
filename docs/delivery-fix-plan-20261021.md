# 报告提交与真实运行记录修复约定

基线f820a62。此前所有实验、题集、阈值、报告与失败保持原样，不重跑覆盖。本轮作者和核对者均为编码助手，不冒充独立或人工验收。

1. 保存之前汇总可独立检查的篇幅、表头、数值、原句、来源和摘录问题，返回字段路径、代码、计量及候选稿哈希。无效来源之后的依赖检查待修复再查，不伪称列出了全部语义问题。反馈条数及长度有界，省略明确计数；拒绝时报告和质量/关联记录不改写。
2. 简述按既有任务约定组织核心答案、必要依据与限制；长摘录放引用字段。超长拒稿移出模型上下文时保留结构化错误，不丢失同时发现的引用问题。保持软目标、硬上限、审稿次数、预算和语义要求，不自动改ID/原句或补原文。
3. 按实际控制流记录工具requested、returned_ok、returned_error、uncertain。错误返回可以来自校验或重复拦截，不能伪称函数实际执行失败；未返回有差额，服务商内部重试不混入工具请求数。read_notes返回有边界的程序快照并登记实际送达部分为execution，审稿使用真实累计记录；只计保留文档版本，不把片段当全库或全文。
4. 计数在检查点中保存和恢复，不重复记账，不恢复不确定操作。程序摘要被截断时不得把未送达内容登记为完整证据。

先检查组合失败不覆盖产物、修订后再审稿、错误反馈不丢失、计数与跨批次/恢复一致及截断边界，再运行全量回归。之后将新四题与源码、模型、配置、代际在真实调用前提交冻结；每题12步、80000等效token，与上一轮同一模型和隔离官方长文档副本，记忆关闭、不联网。新题见knowledge/delivery_cases.json；不调整条件或重新采样来提高分数。

全部原始输出、错误和用量保留；正常结束、报告保存、完整关联/审稿及内容一致分别核对，不将工程通过或调用完成当作阶段12通过。
