## 发现的机制问题

1. **事实数字与名称/定位信息混在一起。** `agent/evidence.py`的通用数字提取会把`FTS5`中的5识别成事实数字，真实错误原句是“FTS5 默认排序为升序（ascending）”。章节4.5和PDF第43页也进入同一检查，从而阻止了部分有原文依据的陈述。这个诊断基于真实错误及源码，不按特定问题增加豁免。本轮不改动该检查后重算成绩。
2. **工具参数和证据引用仍容易误用。** 模型把`source_id/excerpt`放错Schema层级，引用了被裁切片段之外的文字，或提交的结论原句不在当前报告中。部分重复失败触发循环保护。日志共23条工具错误返回，含重复调用被拦截；没有删除这些记录。
3. **收尾预算不足。** 篇幅反复调整、引用重试和额外检索消耗预算，审稿未能完成。原预算是预估软限制，强制收尾仍可能增加实际消耗；五题实际等效token为104969、134323、99175、66937、85577，合计490981，不能宣传为硬上限400000。
4. **范围表述仍有未决问题。** 费用报告正文限定已读片段，但摘要说全库没有合同、发票或任何费用记录，超出本次片段检索能证明的范围。完整性任务拒绝保证无遗漏是正确信号，但同样不能由检索结果证明全库文件数量。本代理保留这些问题，不因最终金额未知或有引用就一律判通过。
