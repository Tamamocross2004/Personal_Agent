# 桌面输入区被裁切修复 · 2026-10-19

用户反馈新建研究后点击没有反应。实际复现发现，历史会话增多后，CSS Grid 的自动最小行高由内容撑开，但最外层固定为窗口高度并隐藏溢出，底部输入/发送区、导入和设置入口被裁掉。示例按钮仍会填入问题，但输入框不可见，看起来像没有响应。

在实际桌面窗口中，视口高度为878 CSS像素，原网格行高1811.33，输入区域底部1811.33，设置入口底部1799.33。修复后网格行高878，输入区域底部878，设置入口底部866，均在可见范围。未发现页面脚本异常；本地服务和新建会话接口正常。布局测量记录保存在本机 `workspace/desktop-layout-geometry.json`，截图为 `workspace/desktop-layout-fixed.png`。

修复将唯一网格行约束为 `minmax(0, 1fr)`，允许侧栏、主栏、成果栏及内部滚动区域收缩；输入区和成果栏固定操作区不参与压缩。历史列表与内容区域在各自栏内滚动。

生产构建通过。扩展后的 `npm run smoke` 使用40条额外的临时DOM历史条目，在1440×940、1280×800、1050×700三种窗口尺寸及成果面板显示/隐藏状态下，直接核对输入、发送、导入、设置和各栏的可见坐标；不再把自动滚动后能点击等同于正常可见。另验证历史列表滚动不移动外层、示例能填入问题、按钮和Enter均发出提交请求，以及原有会话管理操作。两次提交由测试拦截，没有创建研究或调用模型。

本轮仅修改布局和桌面回归，未改Python研究执行逻辑。先前桌面检查依靠自动化点击，未核对可见区域，因此漏掉了该问题；本次回归补齐这一缺口。未将单纯重启作为修复结果。
