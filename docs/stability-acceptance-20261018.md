# 三轮稳定性验收（2026-10-18）

## 验收口径

- 被验收版本：`be72a55`。验收期间不修改实现、题集或评分器，不因失败追加重跑替换结果。
- 独立运行 3 轮，每轮同一套 8 题：DeepSeek `deepseek-chat`，最多 15 步/题、80,000 等效 tokens/题、400,000 等效 tokens/轮、最多 2 次审稿、temperature 0.3。
- 每轮单独输出目录和 SQLite 记忆库；个人研究数据库不参与验收。顺序执行，避免并发请求干扰。
- 记录每题通过率、步骤、任务耗时、等效 token、审稿次数及失败类别；跳过/未运行仍计入 24 个测试位置，不记通过。
- 自动稳定性门槛：24/24 通过，无跳过，所有最终报告审稿完成、无遗留问题且哈希匹配。
- 人工抽查每轮的联网研究、费用计算/图表及记忆追问，核对证据与引用、分项/总额、关键比例、历史与当前用量。发现实质错误时，人工验收不通过，即使自动规则通过。
- 三轮只能提供有限样本，不保证泛化能力或之后每次运行都通过。评分器误判与真实报告错误分开记录，本次不临时修改评分规则。

## 执行命令

先执行全套回归和固定离线评估。然后以下三个独立进程顺序运行，每个进程保持原来的整轮预算：

```powershell
foreach ($roundNumber in 1..3) {
    .\.venv\Scripts\python.exe -m agent.evaluate live --provider deepseek --model deepseek-chat --max-steps 15 --budget 80000 --suite-budget 400000 --review-calls 2 --repeat 1 --out "workspace/evaluations/stability-20261018-round$roundNumber" *> "workspace/stability-20261018-round$roundNumber-console.txt"
}
```

即使某轮退出码为 1，也继续完成其余轮次，保留失败与原始日志；不把独立三轮误当作共享 400,000 预算的一次 `--repeat 3`。

## 人工抽查与问题分类

每轮抽查联网报告及其返回的原文片段、费用计算报告/图表、记忆基线与追问；额外检查全部自动失败题的报告和审稿历史。

### 已确认的评分误判

1. **第一轮 memory_followup：合法 Markdown 表格未被识别。** 主费用表没有外侧竖线，标准表格解析器 `MarkdownIt().enable('table')` 能解析出表头和两行数据，保存时的表头检查也通过；但 `agent.eval_checks.table_rows()` 返回空列表，报两型号均为 0 行。人工核对其输入/输出/总费用为 0.4/0.08/0.48 与 1.8/0.27/2.07，召回和最终审稿通过。本次仍保留自动失败。
2. **第二轮 limited_evidence：条件讨论误作肯定。** 被标记的句子是“这一命题在逻辑上要求三个条件同时成立”，随后逐条说明 B、C 数据条件不满足，摘要与结论均明确否定排名。该条检查不能据此认定报告声称 A 最稳定。
3. **第三轮 limited_evidence：否定措辞漏识别。** 被标记的是“不对 A 最稳定作任何倾向性暗示”，整篇否定跨产品排名。当前否定词规则未覆盖“不对……”形式。

这些是评分器问题，不把相应原始失败静默改为通过；本次验收期间未重评分或放宽标准。

### 审稿流程与内容问题

1. **第一轮 limited_evidence：修订不收敛。** 两次意见推动模型强行选择“两版本合计 51 次”的读法，第二轮又指出 49+48 与合计 51 的解释冲突；第三份报告已无复审额度。最终摘要仍从两个分数换算出“2 次与 3 次未达标记录”，正文却说分母口径不明、不能换算达标次数。属于修订后跨章节一致性问题，而不只是评分误判。
2. **第二轮 limited_evidence：审稿缺少计算器证据。** trace 中确有 `calculator` 成功算出 49/51、48/51 与 97/102 的百分数；独立审稿却称“没有计算记录”，并建议改称手工计算。当前审稿上下文只包含笔记、CSV/代码样本，未包含这些计算器结果，导致误报和不必要修改。
3. **第三轮 official_research：审稿定位范围错误。** 第二次审稿的 quote 来自笔记而非报告，报 `审稿定位原文不在报告中`；次数已用完，状态 failed。本次保留失败，不增加次数或调用重试。
4. **第三轮 official_research：人工发现技术分类错误。** 报告第 3 节（2）把 `sqlite3.Connection` 归入“不支持上下文管理器协议”的类型；但同一报告和所读官方文档均明确它可用作上下文管理器，只是不执行关闭。两种概念被混淆，最终审稿没有给出针对该错误的有效定位。人工内容验收不能记为无问题。

固定题 `limited_evidence` 的“两个版本共 51 次”与两个 51 分母本身存在解释歧义；有的报告按每版本 51 次、有的强行按合计解释。后续应把明确样本量题与有歧义材料题拆开定义，不能在本次验收临时改变题目。

### 抽查中核对正确的部分

- 三轮费用绘图题的 CSV、主要费用表和已目视检查的 PNG 均为：EvalAlpha 输入 0.2、输出 0.08、总额 0.28；EvalBeta 输入 0.9、输出 0.27、总额 1.17。跨型号输入/输出单价倍数为 4.5/3.375，没有把两者混为同一倍数。
- 三轮联网题关于“Connection 上下文管理器不关闭连接，需显式 close 或 closing”的核心结论，均能在本轮实际返回的官方文档片段中找到直接依据；这不覆盖报告附加解释的所有事实。
- 三轮记忆基线与追问的历史日期、固定价格、输入 100000→200000 与输出 10000 不变的口径均核对一致；追问 CSV 均为 0.4/0.08/0.48 与 1.8/0.27/2.07。每轮专用数据库均只有本轮的两条记录，追问均召回本轮 id 1；六个记忆任务的搜索/网页读取/网页笔记工具调用均为 0。正确费用不意味着不存在格式检查误判或审稿问题。
