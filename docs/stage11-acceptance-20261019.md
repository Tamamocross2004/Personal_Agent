# 阶段 11：关键结论证据可追溯功能验收（2026-10-19）

本阶段按证据定位与版本绑定功能收尾；**不认证全文内容正确性**，下面保留开发中发现的语义遗漏与本轮核对范围。交付本次已送达证据索引、选定结论与假设记录、改稿失效检查、同版本审稿和离线核对入口。`mapped` 表示选定结论原句与依据摘录在当前版本可定位；所有记录仍为 `semantic_support=not_certified`。来源存在、代码成功执行、模型审稿无问题均不构成全文真实性认证。

## 实现与约束

- `agent/evidence.py` 保存本轮 `user-1`、实际注入的 `history-1`、`web-N`、成功 `calculation-N`。失败调用不录入计算证据。网页只保存真正交给模型的片段/截断前缀，附 URL、标题、提取文本字符区间 `[start,end)`、UTF-8 SHA-256、UTC 读取时间及抓取时间。缓存全文指纹仅标识版本，不代表全文已读；页面日期保留 `unverified_metadata`，不冒充发布日期，历史创建日期不证明当前价格。
- 索引最多 128 条、总正文 300000 字符、每条 12000 字符前缀；遗漏/截断明确记录，原 ID 不因上下文压缩被重新分配或改写。`read_evidence` 列出保留 ID 或定位某条最多 1600 字符内容，不访问未读缓存。
- `write_report(claims=...)` 最多保存 8 条选定原句，类型为直接资料/计算/依赖假设推断/未知，最多每条 4 个依据。非未知需引用，推断需假设，历史需填写限制（提示要求带记录日期，程序不验证任意限制文本的语义），计算需成功计算来源；这些只是有限结构约束。原句需出现在报告，摘录需在实际保留证据中；只允许空白差异定位，保存的 `excerpt` 是真实原始子串，并保留 `requested_excerpt` 和定位方式，不允许措辞替换。
- 无效关联在写报告前拒绝，保留旧产物；正文改变而未提交新关联时保守使全部旧关联过期，不猜测哪些仍可用。关联为草稿/缺失/过期时不冒充完成。审稿同时绑定报告与依据摘要；仅修改依据也使旧审稿失效，仍受原两次审稿上限及任务预算约束。结构/关联不足先反馈，正常结束前最多一次提醒，不无限重试。
- 报告与审稿使用同一证据包，来源上下文共享去重；输入包上限 14000 JSON 字符，超限明确记录遗漏并令审稿 partial。审稿提示核对版本、条件、行为主体、单位与日期，不是这些语义的通用证明器。成功保存正文但无关联仍可查看，不能算完整证据审稿通过。

## 核对范围与剩余限制

程序独立将用户记录与原问题、历史与实际注入背景、网页与真实 tool_result、计算输入与成功输出逐项交叉核对；检查字符区间、哈希、报告原句、摘录及审稿版本绑定。每份报告的八类产物保留字节 SHA-256，共 336 项，原产物位于 Git 忽略的 `workspace/evaluations`，公开摘要不包含整段网页、用户材料或密钥。哈希不提供外部签名，不能防止连同整份账本一起被恶意重写，也不能从摘要重建本地忽略文件。

编码助手回放核对了两轮证据题的所选结论、摘录、假设与限制。用户价格与缺失项可定位；网页“不自动关闭连接”的原文来自本次实际送达片段；费用为0.48/2.07、差额1.59、倍数4.3125。第二轮输入token占比约95.2%，输入费用占比约83.3%/87.0%，差额中输入侧贡献1.4/1.59约88.1%，与输入和计算一致。两轮条件推断保留“今天”相对表述，未补具体日期；历史价格、创建日期与沿用限制可追溯。本轮没有用重评分替代原始结果。

仍保留以下限制，**不称全文内容通过验收**：

- 两轮provided_scope均有direct复合句包含推导出的4.5倍，而user摘录只给2与9；另一个calculated关联虽有9/2=4.5，direct类型本身仍过宽，不能把作者标注视为正确分类证明。
- 首轮memory_seed部分摘录只到input_cost短前缀或CSV表头，完整共享来源上下文虽含输出费、总额及两行数据，短摘录本身仍非复合结论的完整支持。
- 首轮费用题未选中的“费用差异与调用规模无关”需明确绝对差额与倍数：同比放大用量，倍数不变，但绝对差额随规模放大。关键金额正确不证明所有解释都已合适限定。

这些具体观察进入机器摘要manual_findings，后续应纳入阶段12开发集并以新保留题核对。这里按证据定位、修订失效、审稿绑定与有界修订功能验收；语义分类、最小充分摘录和任意推广解释仍需人工判断。

最终v2原错题的合计表为97/102约95.1%，没有再写98；费用为0.28/1.17，追问为0.48/2.07，历史日期与虚构价格限制保留，也未再声称两型号内部单价比均为1:3。不过memory_seed摘要仍用“乘积效应”描述两个单价倍数，措辞不准确：费用是分项之和，总倍数是相应费用权重的加权关系，而非两个单价倍数的乘积。此项也列入后续语义开发问题，不能把自动42/42当作全文科学解释通过。


模型类型标注仍可能不准：b43 候选的证据首轮 `memory_seed` 把用户给定单价标为 calculated 并引用成功脚本的输入字典，而非 direct/user；程序可定位其出处，但不能认证“给定”与“推导”分类正确。还存在选定复合句只摘出其中一行结果、需结合共享来源上下文核对另一型号的情况。最短数字摘录也不证明单位、条件、因果解释都正确。上述问题如实保留，不将全文逐句或所有类型标注称为通过。

这里的回放核对由本次编码助手执行，不是外部人工盲审。模型审稿不联网、证据打包有上限，未核实全部科学解释或图像像素；未知资料仅表示本次保留范围内的缺口。新增题目参与了开发，是回归集；本阶段对证据六题做两轮、范围七题三轮、原v2九题一轮，不代表阶段12独立保留集和完整三轮稳定性门槛已通过。阶段12尚未开展。

## 用户查看与重跑

在项目根目录查看已有任务，不需要 Key，不产生 API 调用：

```powershell
.\.venv\Scripts\python.exe -m agent.replay "workspace/<任务目录>" --full
.\.venv\Scripts\python.exe -m agent.evidence "workspace/<任务目录>"
```

打开同目录 `report.md`、`report.evidence.json`、`evidence.json`，按 `quote → source_id → excerpt` 核对。`mapped` 的退出码为 0，草稿、未关联、过期或损坏为非零；这不是语义真实性判定。`read_evidence` 是模型可用工具，离线 CLI 使用上面的 `agent.evidence`。

以下真实评估会使用项目 Key 并消耗额度，输出目录必须是尚不存在的新路径。将六题命令另换新目录独立执行第二轮；原v2执行一次；范围命令分别换三个新目录独立执行，共三轮，即为本次矩阵。范围三轮使用独立目录和各自的单组预算，未合并为同一 `--repeat 3` 组。
