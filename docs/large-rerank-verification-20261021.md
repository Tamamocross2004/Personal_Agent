# 十万条语料重排对照（2026-10-21）

本轮采用完整的公开 [C-MTEB/EcomRetrieval](https://huggingface.co/datasets/C-MTEB/EcomRetrieval) 语料和配套 [qrels](https://huggingface.co/datasets/C-MTEB/EcomRetrieval-qrels)，不扩充虚构制度、复制片段或根据基线失分选择题目。原24份制度资料实验及全部历史失败记录保留。

## 固定协议

- 原始资料100,902条，100,902种文本，共3,327,790字符。平均32.98字符，最长121字符；这是大候选库的短文本检索测试，不是长文档或长PDF问答验收。
- 从全部1000道有正标注的问题中，用种子20261021预先抽100题。每题保留原始正标注，不改写题目或补标。完整候选语料全部纳入，没有只为所选题保留相关资料的条件采样。
- 当前抽样每题一个正标注；其余未标注条目按不相关处理。因此Precision@4最高25%，且可能低估未标注但实际相关条目。报告Hit@4、Recall@4、MRR@4、nDCG@4及候选Recall@20，并保留失败题。
- 使用原有生产检索：FTS5最多40条、向量最多40条、RRF常数60、取前20候选，再决定是否调用`BAAI/bge-reranker-v2-m3`。最终取4条，两臂逐题核对候选ID与顺序完全相同。
- 嵌入为项目配置的`Pro/BAAI/bge-m3`、1024维；查询嵌入在比较前单独预热。重排每题首次调用，不把命中缓存的速度当成重排服务延迟。两臂顺序预先随机，关闭先执行41题，开启先执行59题。
- 计时包含生产检索路径中的SQLite读取、Milvus访问、排序和开启臂重排网络请求；不含建库与查询嵌入预热。统计平均、中位数、P95，并报告nDCG逐题改善/退步/持平和固定种子的配对bootstrap区间。
- 本轮不调用聊天模型，避免研究步数、提问策略与报告生成波动混入排序对照。不根据结果调候选数、阈值或验收门槛。

## 隔离与用量

最终实验索引位于`workspace/large-rerank-final-20261021/knowledge`，正式知识库不变。生产导入仍限制50份文档、200万提取字符、5000片段。

`knowledge.large_probe`仅提供基准专用的预分段导入：一条原始资料就是一条chunk，原始pid就是相关性标注单位，不执行相邻资料补充。SQLite元数据、全文索引和Milvus索引均在隔离目录建立，查询直接调用`KnowledgeStore.search`。适配器不挂到生产CLI上传、桌面API或研究工具；它不证明正式桌面已支持十万份文档管理、原文预览和研究。

语料使用固定数据集版本下载，下载文件SHA256、全部问题/标注、两臂顺序、代码指纹、模型身份和预算在首次付费调用前写入`plan.json`。初始估算语料2,301,717 token；实际用量以接口返回为准。嵌入每批32条、最多4个在途请求，整个实验嵌入预算800万输入token，重排预算50万输入token。请求前按估算检查预算，实际用量可能高于估算；超限、未知用量或接口错误停止后续调度，不自动重试或降级。失败时已有在途请求会正常收尾并保留用量。

模型调用只读取本项目`.env`的硅基流动Key。逐请求状态、实际token、耗时、输入哈希、重排索引与分数保存在隔离数据库。没有配置货币费率时按未计价处理，不能写成免费或零成本。

## 中断与恢复记录

1. `workspace/large-rerank-live-20261021`：嵌入服务一次`InternalServerError`后停止，没有自动重试。811次成功请求、25,952条已缓存向量和1次未知用量失败均保留。该目录`complete=false`，不冒充完整实验。
2. `workspace/large-rerank-continue1-20261021`：本代理明确发起一次续跑，先核对新旧`plan.json`逐字节一致，再复制成功缓存及全部原调用记录。完成全部100,902条嵌入；Milvus Lite 3.0在Windows清单覆盖时发生`WinError 183`，索引构建失败，评分尚未开始。原始结果仍为`complete=false`。
3. `workspace/large-rerank-final-20261021`：修复存储兼容性后重新冻结。与上一协议逐字段比较，只有代码指纹变化，数据、模型、问题、顺序和全部评分参数不变。复制全部成功向量和已有调用记录，仅重建本地索引；失败目录没有覆盖。两次续跑的关系、原因和哈希写入各自`continuation.json`。

兼容修复位于`knowledge/vectors.py`：只对核对过的Milvus Lite 3.0、Windows以及它的清单模块，将提交操作绑定到`os.replace`，保留原来的临时文件、fsync、前一版备份及错误传播；不改全局`os.rename`或虚拟环境包文件，不更改向量或排序。原因可对照[Python的Windows文件替换说明](https://docs.python.org/3.11/library/os.html#os.rename)。真实多次flush、关闭重开和检索回归已通过。

服务端失败没有返回用量，始终记为未知；累计已知token只是不含该请求的下界。嵌入上限核对还为该32条批次单列保守容量预留（32×8192 token），不把未知消耗隐去或按零计费。

## 结果

100/100题完整结束，`complete=true`、`source_unchanged=true`。独立检查Milvus实际条数为100,902，每题两臂的20个候选ID和顺序一致，首次重排缓存命中数为0。根据原始命中列表重新计算排名与指标，与实验输出一致。

| 指标，100题均值 | 关闭重排 | 开启重排 |
|---|---:|---:|
| Hit@4 / Recall@4 | 52.00% | 63.00% |
| Precision@4 | 13.00% | 15.75% |
| MRR@4 | 0.4325 | 0.5550 |
| nDCG@4 | 0.4547 | 0.5744 |
| 候选Recall@20 | 77.00% | 77.00% |
| 平均检索耗时 | 1.1970秒 | 2.0452秒 |
| 检索耗时中位数 | 1.1957秒 | 2.0333秒 |
| 检索耗时P95 | 1.2573秒 | 2.1667秒 |

重排在这组题上净增加11题前4条命中，平均增加约0.848秒耗时；新增命中12题、丢失命中1题。按nDCG比较，23题改善、6题退步、71题持平；平均差值+0.1197，固定种子2000次配对bootstrap的95%诊断区间为[+0.0516,+0.1885]。保留全部退步项，不修改原标注。

例如问题`200144`“涂色书小手画画蒙纸版”的已知正例包含“蒙纸学绘画”，关闭时第1条命中，开启后掉出前4条；不能因为新前4条也与涂色相关就改标签抵消退步。`200723`“手控小汽车”的正例由第1名降至第2名，仍命中但排序指标下降。全29个有变化的案例及其排名保存于`validation.json`，完整100题原文和排名保存于`results.json`。

候选Recall@20只有77%，即23题的已知正例根本没有进入重排池，重排无法补回；另外14题虽在候选池内，开启后仍未进入前4条。本轮结果支持“重排能改善这套大候选库的排序”，不支持“重排解决了所有召回问题”或“每道题都变好”。

## 复现

如缺少实验依赖，先安装`pip install -e ".[rag,rag-benchmark]"`。以下命令会创建新目录，并在第二步产生真实API用量：

```powershell
.\.venv\Scripts\python.exe -m knowledge.large_probe --prepare --output workspace/large-rerank-new
.\.venv\Scripts\python.exe -m knowledge.large_probe --live --output workspace/large-rerank-new
```

`--prepare`只下载公开资料并冻结协议，不调用模型。`--live`拒绝源代码/数据/模型身份变化，也拒绝覆盖已有完整或失败结果。原始资料与索引均由gitignore排除，不将大文件或Key提交远程。

## 结论边界

这是公开短文本基准的项目检索对照，不是独立私有保留集；无法排除模型训练时见过公开语料。相关性排序指标不等于报告事实正确率，不替代阶段12验收，不据此认证全文支持或调整自动拒答阈值。
