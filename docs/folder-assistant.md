# 指定文件夹资料助手

阶段15—19已实现本机目录预览、独立索引与手动同步、带引用短答及结果导出；各阶段实际验证记录见下文。阶段12仍未验收。

桌面重启后，左侧点击 **文件夹资料助手** → **① 添加资料文件夹** → 系统目录选择器 → **② 扫描文件清单** → 文件右侧 **打开内容预览**。这些操作均在本地；界面显示相对路径、格式、大小、修改时间及排除/不支持/超限原因。同名文件按目录区分。建库和短答是下一步显式操作，不会在选目录时自动调用云端。

目录授权由原生主进程的单独凭证登记，渲染页面的本地API凭证不能授权任意路径。读取按目录、扫描ID和文件ID定位，不能传任意绝对路径。撤销授权后禁止读取和扫描，已有清单保留，不等于彻底删除历史数据。

点击可读取文件旁的“解析预览”查看内容与来源位置；“上一组/下一组”翻阅，每组50块。文件修改后须重新扫描，不能把新文件当旧版本读取；缓存也必须通过当前文件/目录授权和身份核对。取消授权后已有屏幕内容不等于继续读取能力。

| 格式 | 本地预览与定位 | 首版边界 |
|---|---|---|
| TXT/Markdown | 原始行、提取文本字符区间 | UTF-8/BOM；不执行内容，不渲染HTML或图片 |
| 文本PDF | 真实页码、页内行与字符区间 | 无OCR；无可提取文字明确报错，不还原版式 |
| CSV | 逻辑记录、列值及实际物理行起止 | UTF-8、逗号；引号内换行保留；首行不自动认定为表头，空字符串与零不同 |
| DOCX | 按正文顺序的段落、表格行列、合并原点 | 不推算页码；不含页眉页脚、批注、修订、文本框、图片和嵌套表格 |
| XLSX | 工作表/单元格、类型、格式码、合并范围、隐藏状态 | 不执行宏/外部链接/公式；公式缓存可能过期，无缓存为未知，不做财务计算保证 |

旧DOC/XLS、加密、损坏、编码不支持或资源超限分别保留失败说明。Office包先检查条目/解压大小与XML实体，固定解析器在独立子进程运行，超时20秒停止；不是执行模型生成代码，也不声称具备操作系统级资源沙箱。单份提取最多10000块/100万字符，XLSX源单元格最多50000、5000行、200列（有效矩形范围也受限）；超限明确失败，不悄悄截断成成功。结构化输出中保留源文件哈希、解析器版本、位置及提取文本哈希。

依赖已安装到本项目环境；新安装用`python -m pip install -e ".[desktop,rag,folder]"`，现有桌面安装脚本已包含folder依赖。解析缓存保存在`workspace/folders/parsed`，只保存本地提取记录，临时读取副本在解析后清理；缓存尚无自动清理入口。预览不会把文件发给模型或嵌入服务。重启桌面应用后使用新入口，无需启动新研究。

默认最多2000项（含目录）、200MB总文件字节、单文件20MB、深度12。达到上限明确标记扫描未完成；不静默截取。排除`.env*`、常见密钥、版本库/依赖、应用索引与任务目录；跳过链接、junction、云端占位、网络路径和多硬链接。目录与文件在使用时重新核对身份；读取前核对实际文件句柄路径及扫描身份，前后变化拒绝混读。这是本功能的读取边界，不是整个应用的操作系统沙箱。

CLI（不调用模型）：

```powershell

.\.venv\Scripts\python.exe -m folder_assistant list
.\.venv\Scripts\python.exe -m folder_assistant scan <返回的目录ID>
.\.venv\Scripts\python.exe -m folder_assistant show <目录ID>
.\.venv\Scripts\python.exe -m folder_assistant preview <目录ID> <扫描ID> <文件ID> --offset 0 --limit 50
.\.venv\Scripts\python.exe -m folder_assistant revoke <目录ID>
```

授权与扫描清单默认在`workspace/folders/catalog.sqlite3`，不提交用户文件。`--state-dir`可给CLI指定隔离状态目录。

## 阶段19：导出与本机工作流

短答结束后点击 **⑤ 导出摘要 / 对照表 / 来源清单（本地）**，生成固定任务目录 `workspace/folders/outputs/<任务ID>/`，可点击 **打开导出文件夹**。导出6个文件：

- `summary.md`：摘要、未知项、状态和实际送达证据。
- `comparison.csv`、`comparison.xlsx`：只有问答本身包含对照行时才有数据行；未要求对照不会额外编造字段或计算统计。
- `sources.json`、`sources.csv`：所选文件范围、来源SHA/索引版本/扫描ID和实际送达范围；范围文件不等于模型已读全文。
- `record.json`：问题、固定范围、原始模型响应、请求与真实用量事件，便于核对故障和截断。

CSV以UTF-8 BOM输出，对潜在公式前缀加英文单引号；XLSX将外部字符串固定为字符串单元格，不执行公式、不带宏。记录JSON保留原值供精确核对，CSV防护字符不计作原资料值。未知与空白的值列可以均为空，但status列分别为unknown/blank；已知零为文本0，不擅自填补。

导出不会调用模型，不写入源资料目录。再次导出复用已保存文件并核对哈希；若用户修改导出或导出中断，保留已有文件并提示，不自动覆盖。结果不完整/失败也可导出核对，标题和状态不伪装为通过。

取消授权或移动原目录会阻止扫描/新检索/新问答；已保存的问答、提取版本引用和导出仍可只读查看。在目录选择框选择标记“已撤销，仅历史”的记录。重新授权、重新扫描、同步、再次提问均为显式动作，服务重启不会重跑付费请求。停止无法撤回已发请求；进程中断可能留下用量未知，须核对平台账单后再决定是否新建请求，不支持把未返回响应伪装成精确续跑。

表格索引按真实行组织相邻单元格，保留每个原始单元格定位与元数据；不自动认定首行是表头、不计算公式。超长行仍受原有切片/候选/5500送达字符上限影响，有限片段可能缺少远处上下文。关键词检索可能无匹配，可显式选择混合模式，不自动追加付费调用。

## 阶段20：对象标识与判断边界

首轮短答使用回答格式v2，当前新请求使用下文的v3：对照表把业务对象与来源分开，业务对象名称和值分别绑定本次实际送达的连续原句。对象不能确认则显式保留未知；程序不拿文件名自动代替对象。表格记录位置明确时，跨行拼接对象与值会被拒绝；非结构化文本跨片段关联会提示待核对。

事实整理、推断、差异、明确矛盾、未知分别标示。推断同时展示额外假设和不能确认的部分；有额外假设的内容不能标成原文整理或明确矛盾。差异/矛盾列出双方原句、比较字段及可比条件；明确矛盾还须声明共同范围。程序只检查声明是否齐全和原句是否匹配，不替模型判断真实的可比性或语义蕴含。所有结果仍未正式审稿。

原句匹配不等于完整字段抽取或结论正确。例如，文字确实出现，也可能被模型关联到错误的对象；字段截取是否完整、判断范围是否成立仍需检查。对象未知、重复来源级行和跨片段关联保留提示，不自动修补答案或增加模型调用。格式或引用不符合本次约定时，保留原始响应与具体原因，不能把拒绝格式化算作回答正确。

新格式的Markdown保留推断假设/限制、比较条件与依据原句；CSV/XLSX保留原来的前五列，追加subject_type、subject_quote、value_quote三列。旧记录不重验、不升级、不补原句，也不重复调用模型；已存在的旧导出仍先验证原哈希并复用，不覆盖。新请求不会回退接受旧格式来规避要求。

检索、切片、送达范围和1200输出Token上限未放宽。只查列名可能仅返回表头与相邻一行；这时结构有效也不能证明全表整理完整，相关覆盖问题单独记录，后续阶段22处理。


阶段20首轮实际诊断：8个新问题单次调用，3份形成结构化结果、5份因字段类型不符保留原始响应。主要是模型将subject_quote/value_quote写成字符串、将comparison写为null；另有差异/矛盾缺少relation。原始回复中已有对象名称、零/未知及推断边界的改善，但不能算可用表格交付；整表提问也有后续记录未召回。首轮代码、原始响应与未通过项已经归档，不修改这轮结果。

通用后续修复只将程序实际验证模型生成的JSON Schema加入请求，明确嵌套引用对象、数组和relation结构；没有把字符串强转引用、把null强转数组、放宽校验或改答案。仅此Schema说明修复步骤中的校验函数与模型定义AST签名与首轮一致；随后v3修改为独立的字符区间约定，不追溯改旧记录。使用另一组新资料单次验证，独立保留结果，不重跑原8题计算改善分数。


字符区间约定v3：值和对象名称可以是所引完整句子中的连续片段；所引句子本身仍须逐字匹配实际送达文本，提取值/名称仍须逐字出现在句内，不做单位换算、空白归一化或补字。记录所有匹配位置，不在重复文本中虚构唯一位置。界面“值原文”显示相对本次送达片段的左闭右开字符区间；索引以Unicode码点计，不是源文件字节偏移。表格记录的跨行绑定检查仍保留。

## 阶段22：顺序读取与分批整理

“局部检索问答”保持原召回数量、候选数量和送达限制，适用于查找具体信息。“全量整理”显式选定固定索引与文件范围，按相对路径、原文块顺序遍历已解析文字，不根据问题关键词删除记录。只覆盖已提取文字，不含OCR或解析器遗漏；未恢复跨页表格关系。

先点击 **查看读取计划与首批原文（本地）**，查看提取块数、片段数、字符数与原始位置；继续查看下一批也只在本地，不会发送模型。引用面板的 **查看前后相邻原文（本地，不发送模型）** 展示同文档前后提取块，单块显示前4000字符并标记截断。历史版本引用在撤销目录授权后仍可只读核对。

点击 **开始分批整理（调用模型）** 才发送文字。每批最多6个700字符的连续片段；上下文与主片段合计不超过5500字符。按结构可附实际表格首条记录（不认证为表头）或明确Markdown标题。长行无重叠切分，保留真实块号、页/行/单元格以及Unicode字符区间；不填造表头、转换单位、推断跨表对象关系。PDF仍为带页码的提取行，Office仍用真实结构位置，不能把内部块序号当页码。

每次1至8批、总预算256至50000 Token，默认3批和10000 Token；每批输出仍最多1200 Token，没有提高生产导入上限或检索容量。检查剩余预算后才能发送下一批；失败、用量未知、格式无效或截断时停止，不重试或自动修补。

覆盖记录分开保存：确认送达的输入位置、结构及原句检查通过且未截断的批次范围、尚未送达与尚未完成整理的范围。通过结构检查不证明逐条抽取完整或语义正确。已送达但未形成可用结果的批次仍是未完成范围，**继续整理剩余范围** 会新建任务，显式重发首个未完成批次并另外计费。前次记录、原始响应与导出保持不变；旧版覆盖记录没有处理游标时，新任务从其保存批次定位首个未完成位置，不修改旧记录。

逐批结果可切换查看，每批保留独立请求、原始输出和检查结果。导出保留批次列、覆盖记录和全部原始任务数据，不由程序合并去重或虚构统一结论；续读前次结果保留在原任务导出。

## 阶段23：输出空间与显式拆小重做

阶段22段落描述当时的固定分批。当前新任务默认采用 **自动匹配输出空间**，仍在相同700字符片段、最多6个主片段及5500送达字符限制内顺序读取；不改变读取计划、来源结构或回答v3校验。

在④提问处展开 **输出额度与分批设置（下次新任务）**：

- 每次输出Token上限：默认1200，可显式设为128至4096；还受项目单次上限和当前剩余预算限制，不会提高任务总预算。
- 分批策略：自动策略从设定片段上限向下选取预计能容纳的批次；固定策略直接使用片段上限，仍检查实际剩余预算，可能截断。
- 每批片段上限：1至6，默认6。自动策略可以实际发送更少。
- 每条预计字段数：1至12，默认1。多字段对照可填写实际预计数量；启用字段规划后，按用户预估与已规划字段数量的较大值估算，续读沿用原规划。**只参与资源估算**，不会限制答案字段、修改问题、提高额度或放宽校验。保存的分批记录分别展示用户预估、规划数量和实际采用的估算数量。

估算版本1用真实送达文本、v3 JSON外壳、每个原文块一条finding与预计数量的comparison估算正文，假定引用全文及32字符标签；这些是明确的近似，不是保证。实际输出可能更长、更短或不遵守格式。单片段仍装不下时先停止并保留估算记录，不跳过该段。可在新任务显式调整额度或分批策略。

思考与正文共享输出上限。系统只参考服务已返回的reasoning_tokens子项，并保存已知最大值供后续批次/续读估算；没有返回时标为未知，不把未知写成已知零。没有独立的“思考Token配额”，也没有按低中高猜定消耗比例。reasoning_tokens是output_tokens的子集，不重复加入账单汇总。

已确认返回但格式无效或截断的多片段批次，显示 **拆小重做未完成批次（新任务，重新计费）**。点击后：

1. 固定原问题、文件、索引和模型强度，继承首个未完成位置。
2. 将该失败批次的片段上限至少减半，仅处理它原来的区间；预算、输出额度、策略及批数来自上方设置。

4. 到原失败范围末尾即停止，其他未完成范围需另点继续。若再次失败仍停止，不递归自动重发；单片段不能再按片段拆分，未知用量也不能直接拆小重发。

## 阶段24：范围与任务链

查看保存问答时，**范围与任务链 · 本地查看** 自动读取原任务及沿resume_from连接的续读/重做记录。它只解释保存事实，不重新调用模型、不运行答案校验、不更新旧任务。不会混入从同一原任务另开的其他分支。

全量整理按固定来源的真实主片段去重，显示四种记录状态：

- **无确认发送记录**：在当前可读取的任务链中没有确认返回或不确定请求记录；不代表其他分支或缺失历史中绝未发送。

局部检索只显示确认返回的有限证据数，全文阅读率不适用。两种模式都注明固定索引与文件范围，只覆盖已解析文字，不含OCR及提取遗漏。内容可靠性继续由单独流程判断，阶段12状态不变。

## 阶段29：从局部短答创建全量整理

在 **已保存的短答** 中选择一份已结束的局部检索问答，找到 **需要整理所选文件的全部已解析文字？**。

## 阶段30–31：持续整理与字段意图

选择 **全量整理** 后，或在已保存局部短答的全量整理入口中，启用 **持续整理至末尾**。它使用同一个总预算逐批读取，显式调用上限1至64次，初始值16；不再受普通模式的3批默认值限制，但不会增加预算、输出上限或自动重试。达到末尾、预算/调用上限、输出空间，或者出现截断、校验失败、未知用量和停止请求时，仍会结束并保留部分结果。

桌面持续整理默认勾选 **先按问题区分属性事实与文字摘录（增加一次模型调用）**，可关闭。此步骤只向模型发送用户问题，不发送资料，生成字段名、解释方式及其在问题中的依据原句。例如，同一任务可以要求“读数”取得实际属性值，同时要求“标签”摘录文字本身；缺失说明和字面标签不应互相影响。

规划不是标准答案：程序只检查结构、重复字段及名称/原句是否来自用户问题，不能认证它理解正确。后续资料请求携带字段意图作为任务说明，仍只以实际送达原文作为证据，仍由原v3校验检查引用和取值。没有按不确定性词语自动替换状态，也不修改原始模型响应。

规划调用计入同一总预算和模型调用上限，最多1024输出Token，且受用户单次输出额度和实际剩余预算约束；不是额外免费调用，也不会重新增加总预算。首次规划若只有1次调用额度，本次只会规划，不发送资料；本地预览明确提示。已有规划的续读不再占用规划调用，1次额度可以用于资料整理。规划失败、截断或用量未知，会保留原始响应并停止资料整理。显式续读固定原问题和来源，继承同问题的规划，不重新规划；若要换问题或重新解释字段，请新建任务。

保存结果中可展开 **字段意图规划** 查看字段模式、问题依据、原始响应及复用来源。各批“发送构成”包含字段意图的输入估算。`record.json`导出保留规划与原始请求，不覆盖旧结果。预览在规划前只做本地估算，真正首批会在规划返回后按实际用量与元数据重新计算；预览不会代替规划调用。

阶段32起，新建全量整理及续读预览分别显示首次调用发送问题还是资料、规划输入估算与输出上限，以及资料范围是否仍为规划前的临时估算。预算不足以规划时不会显示可发送资料；首次仅规划时首批资料数为0。规划取消、调用准备失败、预算不足、服务返回用量超预算分别记录，不停留在“准备中”；不修补或覆盖旧任务的状态。

CLI/API为了避免隐式增加调用，规划默认关闭。CLI须同时显式选择持续整理与规划；下面的50000预算、2400输出是示例指定值，不是新默认：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m folder_assistant ask <目录ID> "整理读数，并逐字摘录标签" --strategy exhaustive --read-to-end --plan-fields --max-calls 16 --budget 50000 --output-tokens 2400 --expected-fields 2
.\.venv\Scripts\python.exe -X utf8 -m folder_assistant full-reading <局部问答任务ID> --read-to-end --plan-fields --max-calls 16 --budget 50000 --output-tokens 2400
# 核对上一行本地预览后，用相同参数再加 --plan-hash 返回的哈希 才会调用模型。
```

普通模式仍默认3批、10000总预算、1200单次输出，无字段规划调用。仍只覆盖已解析文字，不包括OCR或未提取内容；预算不足时可能部分完成，送达不保证完整提取。阶段12状态不变。[阶段30诊断](stage30-verification-20261023.md)、[阶段31复检](stage31-verification-20261023.md)。
