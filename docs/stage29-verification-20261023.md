# 阶段29：从局部短答显式创建全量整理

日期：2026-10-23。基线：`8b1383c`（stage-28）。复核者：coding_assistant，非独立人工审稿。阶段12仍未验收。

## 解决的行为问题

阶段28的DOCX问题只召回了表头及第一条数据行，第二条没有送达。模型在未知项里说明了范围限制；这不能解释为它读过全文后漏抽。本阶段增加从局部问答通向全量整理的明确入口，使用户可以核对并选择读取原文件的全部已解析文字。

预览与启动共用任务参数解析及既有分批估算。沿用原问题、文件选择、索引版本和强度，从0开始新任务，保存原任务ID及计划哈希；不沿用旧答案、历史背景或进度。预览没有云端请求，启动另行计费；设置或有效模型配置变化时哈希不再有效。源任务必须为已结束的局部问答；撤权、跨目录、错误来源、混用续读/拆小重做等情况拒绝。

桌面展示总片段、首批原文、文件名、预算和批数；控制参数变化后隐藏旧的启动入口，须重新预览。CLI提供`full-reading <局部任务ID>`本地预览及`--plan-hash`显式启动。操作步骤见[使用说明](folder-assistant.md#阶段29从局部短答创建全量整理)。

## 通用性与保留边界

没有在生产代码识别“全部”等查询关键词，也没有样例对象名、答案修补、未知字串转状态或按值不等自动判冲突的规则。`contracts.py`、生成说明、回答v3校验、检索召回、700字符分段、分批算法、默认10000预算/1200输出/3批及生产容量都保持原样。

所有旧记录保持原结论。本阶段没有重新跑或改判阶段28题目，没有新增真实聊天、嵌入或重排请求；新的验证提供工程与送达范围证据，不提供模型语义质量提升率。

## 验证内容

- 新DOCX含表头及9条数据行。原局部检索只召回部分行，显式新任务按2段固定分批送达全部10个主片段。测试在原问答之后删除DOCX并重建索引，新任务仍使用旧索引和原选择，未夹带另一份TXT。原短答与原导出字节保持不变。
- 测试替身每次只输出首段摘录，五批仅形成5条对照项：即使10段全部送达且结构可用，也不把它说成全部字段已正确抽取。
- 12段新TXT在局部检索无命中时仍保持局部问答；显式全量任务设1批、每批2段后仅送达2段，剩余10段保持部分完成，不增加预算或自动续读。
- 预算、输出、批数、分批方式、片段数、预计字段数及有效模型上限变化会拒绝旧预览哈希；256 Token预览不产生调用，显示无法发送；源任务未知用量仍显示账单核对提示。
- 隔离Electron验证本地预览不创建新问答、参数变化令预览失效、草稿不替换原问题、显式开始后新建独立任务、原记录/费用不变。测试只使用假嵌入及假聊天，源文件不变；关闭的仅为测试实例。
