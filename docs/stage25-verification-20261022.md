# 阶段25：持续资料项目

用户选择优先实现“围绕同一结果持续追问、修订和增量更新”。本阶段增加本地资料项目，不更换Agent框架，不更改回答v3校验或旧任务结果。目标和字段由用户配置，不用题目关键词、预期答案或测试分数作为生产规则。阶段12仍未验收。

## 实现

`folder_assistant/projects.py`保存项目、不可覆盖的结果版本、操作准备与追问关联。设置采用修订号、处理采用父版本及计划哈希，启动时核对当前状态。准备先持久化，再启动一次既有FolderJobs任务；读取已结束操作时用事务完成新结果版，刷新幂等，不重发模型。原始问答及其用量/失败记录不修改。

首次整理以整个已建库目录为范围。增量按文件SHA识别新增、变化和删除，未完成文件继续列为待处理；未受影响批次保留其原索引、源SHA和引用。变化文件所涉混合批次会整体失效，并扩大重处理文件范围。定点修订按用户选择的文件建立新版本；继续使用既有固定读取游标。覆盖只统计原文主片段对应的可用结构，不宣称字段完整。

版本追问重新查询该版来源；历史结果及最近两轮同版对话仅作有界背景，新引用仍只允许实际送达原文。追问不改变项目头版本。新项目汇总导出按原任务/批次排列，保留原值、判断限制及来源，不自动合并业务对象或补全漏项。

桌面提供创建、设置、预览、处理、停止、版本切换、追问、引用及统一导出；扫描后恢复同一次会话内项目选择。操作说明见[持续资料项目](folder-projects.md)。

## 有限真实诊断

[调用前计划](stage25-live-plan-20261022.json)冻结新资料、预定修改、运行文件、模型配置及总限制。两份TXT包含两台设备的流量/功率；先各用一批整理，然后仅将第二份功率32 W改为34 W，扫描/同步后更新，最后追问第一台设备的流量。没有重跑失败或据结果调代码/标准。

| 步骤 | 结果 |
|---|---|
| 首版 | 两份资料各一批，4个对象字段匹配原文，保留0 L/min和单位 |
| 增量版 | 新证据只取pump-b.txt；复用pump-a原批次及原索引；当前汇总4个字段，第二台功率为34 W |
| 追问 | 回答NR-51流量0 L/min，引用重新送达原句；项目头不变 |
| 历史 | 原版仍为32 W，原版结构、引用和导出保持原样 |

使用项目`.env`的deepseek-flash默认非思考与硅基流动嵌入，零重试；单次输出1200，每操作14000预算，固定每批1段、最多2批。实际聊天4次、嵌入2次、重排0次，已知10189 Token，无用量未知，人民币总费用未定价。预算与生产容量不提高。

本轮是编码助手对两份合成资料的有限流程核对，没有独立人工审稿，也没有验证扫描件、大表、跨文件关联或通用正确率。格式正确、字面字段匹配和旧版不变分别检查，不称为阶段12通过。完整原响应、项目数据库、两版导出、预定编辑前原文及运行快照在workspace/stage25-live-20261022；机器记录保存哈希。

传输边界另报：计划中“unchanged_a_not_resent”若按“请求任何位置都不再包含A的文字”严格解释，本轮未满足。A没有成为更新请求的新证据，也没有新增A的抽取批次，但历史整理背景仍含A的旧答案和引用文字，会随请求再次发送并计入Token。不能把“仅重新处理B”说成“只传输B的全部文字”。本轮未为这项指标修改背景策略或重跑，该限制在机器记录中保留。
