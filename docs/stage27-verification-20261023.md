# 阶段27：选择历史背景与发送构成

本阶段减少资料项目中无关历史文字的重复发送，保留原文证据、生成说明、回答v3校验、默认输出1200、预算与生产容量。没有对已有答案做删行、补值、重写或重新计分。阶段12仍未验收。

## 通用策略

`Projects._context()`将候选背景固定在新操作的本地输入中；更新与续读不选择旧答案或对话。修订候选先限定到处理文件，追问默认允许旧结果背景，用户可关闭。最近两轮同版问答默认关闭，勾选后才发送；推断的假设、限制与陈述一起保留，不能只截出结论当事实。

新模块`project_context.py`在构造每次实际messages时，按文件ID、文件SHA、提取块ID和文字SHA匹配候选批次。原批次的所有来源必须都出现在这次实际证据中，才发送整项旧结果；不同版本、局部文字、缺少身份或混合来源不全就省略，不改写旧答案来适配范围。它是确定性来源匹配，不是语义重排，不使用领域词、对象名称或测试预期规则。

候选和可选对话共用原约6000字符本地预算，对话最多两轮、约2000字符，过大的项整项省略。该上限包含候选身份元数据，实际可用旧文字可能比过去少；匹配前未纳入的候选和匹配时省略的批次分别统计。不能保证所有语义相关历史都被选中。当前原文证据、引用和字段要求保持原样，回答仍只能按本次原文给出依据。

`prepare_messages()`同时用于分批估算和实际请求；本地候选、选择清单与估算不进入messages。请求保存`transmission`：系统说明、问题、证据、范围、项目要求及历史背景的字符与粗略Token，证据身份、实际选中的原任务/批次、对话任务和省略计数。各部分估算不是独立账单，不能相加代替供应商总用量。旧记录缺少该字段就不补算，不触发调用或旧导出覆盖。

## 桌面与接口

重启应用，在项目操作的 **首批发送预览** 查看第一批估算；追问填写问题后展开 **追问发送预览**。默认勾选“带上与本次原文完全匹配的旧结果”，不勾选“带上最近两轮对话”。若承接“刚才那个”等问法，可显式带上最近对话；也可关闭旧结果背景，只按当前检索证据回答。

新`POST /api/folder-projects/{id}/followups/preview`只做固定版本的本地关键词查询，不调用嵌入、重排或聊天。桌面携带预览计划哈希启动，背景/设置变化就拒绝旧计划；实际仍在任务中重新检索、按实际证据筛选并重新核算预算。无命中时不调用聊天，不从旧答案补依据。现有接口调用者不带哈希仍可直接显式新建请求，兼容旧调用方式。

保存的追问可展开实际发送构成；普通问答历史按所选批次显示该批request，避免误显示任务最后一批的清单。新任务摘要导出包含保存的发送构成；项目版汇总继续指向原任务和批次，完整messages/响应在原任务记录中。历史版、原任务与旧导出不修改。

新策略不保证任何场景“完全不发送未变化文字”：混合批次依赖会扩大新证据范围，问题或用户目标可能含同样文字，显式带上对话也会重发历史。旧策略与新策略分别保存；阶段25的历史“不重发任何A文字”失败不改判。
