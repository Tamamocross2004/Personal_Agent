## 实现与使用边界

- `agent/task_contract.py` 从当前用户请求保守提取明确约束，保存 `task_contract.json`。包含原问题指纹、明确必答标签、材料范围、联网/统计要求、长度、文件及表头等。原始问题始终有效，未提取不表示可忽略；历史记录、网页、引述及代码示例不主动增加任务指令。冲突或无法可靠解释的长度表达记为歧义，不擅自补假设。
- `main.py`、`ResearchSession`、规划、Agent、工具注册、保存与审稿共享约定。压缩上下文仍保留约定；连续新任务重新提取，不能继承上一任务的字数限制。明确禁止联网时不注册搜索、读取网页和网页笔记工具；这不是 Python 网络沙箱。
- 格式和明确长度是保存前检查；整稿、追加、局部 patch 均检查合并后的报告。超限反馈实际计数、应减少的数量与计量单位，拒绝时不修改旧报告及质量/审稿记录、不调用审稿。`complete=false` 仍只是草稿，不能声称完成交付；结束时再次检查最终文件并刷新与其哈希绑定的记录。
- 统计结果与独立性等前提只产生可定位观察，语义审稿结合原问题、给定资料及成功计算核对。否定“未做检验”与真正结果分开处理。有限规则不覆盖所有表达，不能把 observations 为空当作没有范围问题。
- 默认简述目标约500个可见正文字符；超过1000时完整稿需给出至少20字符的 `brief_extension_reason`，供审稿判断必要性。该提交策略不是用户硬上限，理由不是自动豁免，详细任务不套用这一目标。当前真实简述仍有599–999字符的稿件，不能宣称软目标稳定达到。
- 沿用原来带版本哈希的局部 patch，不新增预算或审稿次数。新增英文/汉字专用长度修订反馈，防止模型反复删除不计量字符。同步修复数字四则算式检查对连等式右侧只截取首个数的误报；检查完整右式及后续等式，仍采用受限 AST，不运行表达式代码，不支持任意数学证明。

篇幅采用以下公开口径，写入约定及报告检查记录：

| 要求 | 计量 |
|---|---|
| 字、字符、混合文本 | Markdown 可见文本的非空白 Unicode 字符，含标点、数字和英文 |
| 中文字符 | 汉字编码范围，不计英文、数字、空白或标点 |
| 英文单词 | 字母词，词内连字符和撇号保留为一个词 |
| 正文 | 包括标题、章节名、表格、代码；排除明确的参考资料章节 |
| 全文 | 包括参考资料、标题、表格、代码 |
| 链接 | 隐藏目标不计，显示出来的 URL 计入 |

当前自动提取支持有限的阿拉伯数字“最多/不超过/以内”等表达和明确更正；中文数字、模糊范围及“某类内容不计入”等复杂例外尚不自动解释。保留原问题供人工判断，不声称自然语言范围解析完备。任务目录新增 `<报告名>.contract.json`，记录请求/报告指纹、计量、错误、观察和扩展理由。
